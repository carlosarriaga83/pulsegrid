# Servo ESP32

Firmware MicroPython para el controlador Waveshare Servo Driver con ESP32 y servos ST/STS. El dispositivo se administra por Pulsegrid y las actualizaciones deben publicarse y aplicarse por OTA; no se presupone acceso USB/COM.

El perfil usa un unico `config.py` con Wi-Fi, API URL HTTPS, `DEVICE_CODE`, Device ID, comandos y sentido. El código se deriva determinísticamente de la MAC para que pueda volver a calcularse en el quemador; no es un secreto: cualquiera que conozca la MAC puede calcularlo e imitar el dispositivo. El cloud guarda solo su hash. La API key de usuario, si se usa para integraciones externas, no es una credencial del firmware.

Archivos incluidos en un release OTA: `main.py`, `cloud_client.py`, `board_led.py`, `captive_portal.py`, `cortina.py`, `servo_calibration.py`, `stservo.py`, `boot.py`, `ota_boot.py`, `pulsegrid_ota.py` y `wifi_recovery.py`. `config.py` se genera durante la provision y no se reemplaza por OTA.

`main.py` ejecuta localmente el control y el muestreo del encoder en ciclos de 10 ms. El cliente conserva una conexión HTTPS/TLS persistente para reutilizar el canal cifrado y evitar un handshake por cada consulta; el servidor renueva conexiones cerradas y el cliente fuerza una renovación cada 15 minutos. Durante el movimiento solo se consultan comandos prioritarios de parada/cancelación, sin telemetría ni comandos generales; el ACK del comando que inició el movimiento se difiere hasta que el control local termina de leer el encoder y detener el servo. Así, HTTPS no retrasa el muestreo local ni la parada, y la parada remota sigue disponible. La calibración segura también está disponible sin cloud en la página local del ESP (`http://<IP-del-ESP>/` por Wi-Fi o `http://192.168.4.1/` desde el AP de recuperación). La página informa el encoder, ofrece la prueba lenta, pasos supervisados de hasta una vuelta y parada/cancelación local. El portal usa un hilo de 8 KB y lee las solicitudes en bloques de 512 bytes, limitando el cuerpo de formularios a 1024 bytes para reducir picos de memoria; se evita un hilo cloud para conservar memoria interna del ESP32. El transporte limita los buffers del socket a 512 bytes y registra la memoria libre de MicroPython y del heap ESP-IDF antes del handshake TLS y después de recuperar un `ENOMEM`.

Para ESP32 que aún fallen durante el handshake, hay un perfil MicroPython de bajo consumo TLS en [micropython-board/README.md](micropython-board/README.md); requiere compilar y flashear una imagen personalizada, no se instala mediante OTA.

La placa Waveshare usa un RGB WS2812 en GPIO23. `board_led.py` controla los píxeles 0 y 1 del indicador integrado: verde cuando hay respuesta reciente de Pulsegrid, amarillo durante el aprovisionamiento (sin código registrado), rojo si el dispositivo registrado no tiene Wi-Fi o el cloud lleva más de 30 s sin responder y ámbar intermitente durante la recuperación Wi-Fi. Para abrir el portal aunque la red guardada todavía conecte, corta y restablece la alimentación tres veces rápidamente; el AP de configuración permanece activo hasta guardar las nuevas credenciales. La secuencia se cancela tras 30 s de funcionamiento estable. `led.configure` habilita o apaga la indicación sin alterar el estado detectado.

Los comandos generales ESP se consultan cada segundo y cada 200 ms durante la calibración cuando el mecanismo está detenido; durante movimiento se consulta solo la cola prioritaria de parada/cancelación cada segundo. La telemetría se envía cada 2 s normalmente y cada 500 ms durante la calibración, únicamente en reposo y usando snapshots del encoder leídos por el bucle local.

El adaptador `cortina.py` mantiene la superficie de movimiento del cloud (`curtain.open`, `curtain.close`, `curtain.stop`, `curtain.move`) sobre el bus STServo. Tambien implementa el asistente de calibracion (`blind.setMotorSide`, `blind.beginCalibration`, `blind.markDeployed`, `blind.markRolled`, `blind.jog`) y persiste los extremos, lado del motor, porcentaje objetivo y recorrido absoluto. Los estados `blind_state.py` y `multiturn_state.py` quedan fuera de OTA y de la limpieza del perfil del quemador; sus escrituras usan temporal y respaldo para recuperarse de un reset durante el guardado. Si un reset interrumpe un movimiento, se conserva la calibracion pero la posicion queda marcada para recuperacion. Un borrado completo de flash sí elimina esos archivos.

OTA ya escribe cada archivo en bloques de 512 bytes directamente al staging de flash (`.pulsegrid_ota/stage`); no carga el firmware completo en RAM. Acepta `Content-Length` y `chunked`, valida tamaño y SHA-256 antes de activar el release y conserva backup transaccional hasta confirmar el arranque. Tiene timeout de 30 s, reintenta una vez ante timeout, importa TLS bajo demanda y recolecta memoria tras abrir TCP y antes del handshake; si falla, registra la fase exacta. Alimenta el watchdog durante la operación normal. Los archivos persistentes de calibración no forman parte del release. El cliente cloud también recolecta antes del handshake y aplica espera exponencial hasta 60 s tras errores. Toda autenticación del dispositivo viaja exclusivamente por HTTPS.
